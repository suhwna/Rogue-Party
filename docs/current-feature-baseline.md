# 현재 기능 기준표

이 문서는 `docs/full-modernization-plan.md`의 Phase 진행 중 반드시 유지해야 하는 회귀 방지 기준이다.

## 실행/접속

- `npm start`로 기존 Node 서버가 실행된다.
- 기본 포트는 `5173`이며, `PORT` 환경변수로 변경할 수 있다.
- `/`는 기존 `public/index.html`을 제공한다.
- `/rooms`는 공개 방 목록 JSON을 반환한다.
- `/vendor/pixi.js`는 `node_modules/pixi.js/dist/pixi.js`를 제공한다.
- `/client.js`, `/pixi-renderer.js`, `/styles.css`는 기존 public 파일을 제공한다.

## 방/로비

- 방 생성, 방 코드 입장, 방 리스트 클릭 입장이 가능하다.
- 빈 방은 목록에서 제외되고, 가득 찬 방은 클릭 비활성 상태로 표시된다.
- 대기방에서 직업을 자유롭게 변경할 수 있다.
- 대기방에서 평타, 대시, 직업 스킬 테스트가 가능해야 한다.
- 준비 완료 후 방장이 게임을 시작할 수 있다.
- 봇 추가/제거와 관전자 모드가 유지되어야 한다.

## 진행 루프

- 게임 시작 후 지도 투표로 다음 스테이지를 선택한다.
- 모든 플레이어가 투표하면 즉시 다음 스테이지로 진행한다.
- 일반, 엘리트, 준보스, 보스, 보상, 지키기, 막기, 랜덤 타입이 유지되어야 한다.
- 3챕터 구조와 챕터 마지막 보스방이 유지되어야 한다.
- 스테이지 실패 또는 전체 클리어 시 결과창을 표시하고 로비로 복귀할 수 있어야 한다.

## 전투/성장

- 서버 권위 판정으로 이동, 공격, 스킬, 투사체, 충돌, 피해가 처리된다.
- 플레이어 수에 따른 난이도 보정이 유지되어야 한다.
- 직업별 대시/스탯 차별화가 유지되어야 한다.
- 경험치는 바닥 드랍을 획득하는 방식이어야 한다.
- 레벨업은 스킬 강화 3택1 선택으로 처리한다.
- 유물은 몬스터/보상 상자 드랍으로 획득한다.
- 유물은 직업에 맞는 후보만 나오며 중복 상한을 가진다.

## 그래픽/UX

- PixiJS 렌더러가 우선 사용되고 Canvas fallback이 남아 있어야 한다.
- 스킬 쿨다운은 슬롯별 회색 overlay 방식으로 표시된다.
- 하단에는 파티원 HP/레벨과 내 유물 목록이 표시된다.
- 플레이어 위에는 HP와 대시 쿨타임 게이지가 표시된다.
- 지도/유물/스킬/결과 UI가 전투 시야를 과도하게 막으면 안 된다.

## 네트워크/안전

- WebSocket `ping`/`pong` heartbeat가 유지되어야 한다.
- 끊김 후 제한된 backoff reconnect가 유지되어야 한다.
- 서버는 큰 패킷, 잘못된 메시지 타입, 위험한 id 값을 거부해야 한다.
- 클라이언트 입력 sequence는 서버에서 안전 범위로 보정되어야 한다.
